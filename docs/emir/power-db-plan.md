## 1. 定位与依赖

- **职责**：没有外部文件输入。从上游五个数据库取数据，逐实例算出内部
  功耗、开关功耗、漏电功耗与合计，按电源引脚归属；同时留下逐引脚的能
  量中间数据与负载电容，供电流数据库（⑩）合成电流。
- **直接前驱**（显式传参）：单元库数据库（①，Liberty 的能量表、引脚电
  容、逐状态漏电、电源地引脚、库级电压映射）、波形数据库（⑧，逐实例
  引脚的活动原始量）、时序数据库（⑦，逐引脚的转换时间）、设计数据库
  （③，实例与连接、引脚的驱动 / 接收关系、分区）、寄生数据库（⑤，
  网负载）。
- **下游消费者**：电流数据库（⑩）——已定原则是「电流由能量数据与负
  载电容合成，不用功耗除以电压」（裁定 7）。
- **首期不做**（列演进，§10）：活动传播、时钟门控单元的专门处理、宏单
  元按工作模式的功耗、电源关断域、电平转换单元、动态（随时间变化
  的）功耗。

## 3. 计算口径

全部逐实例进行。记观测总时长为 D（秒）；实例某个引脚在 D 内的上升
沿次数、下降沿次数为 N↑、N↓。

### 3.1 活动的推导（裁定 19：由功耗库推导）

波形数据库只存原始量，翻转率与静态概率在这里推：

- 翻转次数直接用原始计数 N↑、N↓（不先折算成「率」再乘回时长——
  避免两次舍入）。
- 静态概率（为高的概率）P1 = T1 ÷ (T0 + T1 + TX + TZ)。分母是否含未知
  态与高阻态，**沿用该波形库汇总里记录的口径设置**（默认含），功耗库
  不另设开关——同一个波形库导出的数字不能有两套解释。
- 引脚在波形库里没有活动条目：取该波形库汇总里的缺省翻转率与缺省静
  态概率（翻转次数 = 缺省翻转率 × D），并计数。**不做活动传播**（把输
  入引脚的活动沿逻辑推到内部引脚与输出引脚）——首版没有传播引擎，列
  演进。
- 时钟引脚没有活动条目时不特殊处理（同上）。两个参照的做法不同
  （OpenSTA 给每周期 2 次、RedHawk-SC 不给缺省），见待裁定 4。

### 3.2 负载电容

实例输出引脚驱动的网，其负载电容

  C_load = Σ 接收引脚的引脚电容 + 网的互连电容

- 接收引脚 = 该网上带接收标记的非端口连接条目（连接三元组唯一的设
  计库连接表）；引脚电容取单元库的 `capacitance`，为 0 时取上升、下
  降电容的平均。
- 互连电容取寄生库该网的条目：对地合计 + 耦合系数 × 耦合合计。耦合
  系数默认 1（设置项，待裁定 6）。缩减形态的网只有行首值可用，直接取
  行首值。寄生库里没有这张网：互连电容按 0 并计数。
- 端口驱动的网（输入端口把信号送进块内）：接收引脚照常累加，没有额
  外的片外负载。

### 3.3 内部功耗

对单元的每个内部功耗组（挂在引脚 p 上，相关引脚 r，条件表达式 w，
上升能量表与下降能量表）：

- 查表：E↑、E↓ = 在（输入转换时间、输出负载电容）处插值。输入转换
  时间取相关引脚 r 上的上升 / 下降转换时间（时序库的区间中点；缺
  失时用缺省转换时间并计数）。输出负载：组挂在输出引脚上时取 3.2
  算出的 C_load；组挂在输入引脚上时取 0（OpenSTA 同款：输入引脚内
  部功耗的下标只有输入转换时间有效）。
- 沿分开算：组挂在输入引脚上 → 能量 = N↑(r) × E↑ + N↓(r) × E↓；组
  挂在输出引脚 p 上 → 能量 = N↑(p) × E↑ + N↓(p) × E↓。fly 的波形库
  有分沿的计数，这是比「取平均再乘总次数」更直接的做法。
- 条件表达式的权重：同一引脚上的全部内部功耗组都参与，各乘一个权
  重后相加（不是只选一组——OpenSTA 同款）。权重 = 条件为真的概率，
  条件里的引脚代入该实例引脚的静态概率（相互独立假设）。条件里的引
  脚不是本实例的引脚（例如触发器的内部状态变量）时取 0.5 并计数。
  没有条件表达式的组权重为 1。同一引脚上的组权重之和 S：S ≤ 1 时若
  其中有无条件组，无条件组补足 1 − S；各组都带条件且 S < 1 时按 S
  归一（未覆盖的状态不另计）。S > 1（条件重叠）时按 S 归一。
- 单元的能量 = 各组能量之和。平均功率 = 能量 ÷ D。
- 单元没有任何内部功耗组：内部功耗记 0 并计数（数据缺口，不猜）。

### 3.4 开关功耗

只在输出引脚上算：能量 = (N↑ + N↓) × ½ × C_load × V²。V 取该引脚
供电归属（`related_power_pin`，缺省为单元的主电源引脚）的电压名在库
级电压映射里的值；取不到用库的标称电压并计数。

### 3.5 漏电功耗

- 逐状态组按「条件为真的概率」加权求和，条件里的引脚同 3.3 取静态概
  率。
- 条件未覆盖的状态（各组概率之和小于 1 的部分）：有不带条件的逐
  状态组时用它补；没有时用单元的 `cell_leakage_power`
  补；两者都没有时只算已覆盖的部分。
- 没有任何逐状态组：漏电 = `cell_leakage_power`。两者都没有：记 0 并
  计数。

### 3.6 归属与产出

- 内部功耗与开关功耗归到发生翻转的引脚的供电归属引脚；漏电归到单元
  的主电源引脚。按「实例 × 电源引脚」各存一份分项与合计。地引脚上的
  电流由电流库对称处理，功耗库只管电源引脚。
- 逐引脚的能量中间数据（供电流库）：每个输出引脚的上升 / 下降次数、
  该沿的内部能量（每次翻转多少焦）、C_load、V；每个输入引脚的上升 /
  下降次数与该沿的内部能量。

### 3.7 单位

内部能量表的原值按库头单位换算成焦：功率单位 × 时间单位（纳瓦 × 纳
秒 = 皮焦）。漏电按功率单位换算成瓦。电容飞法、电压伏。平均功率 =
能量 ÷ D。Liberty 规范对内部能量表单位的规定原文没有取到——按
OpenSTA 的实现口径处理，列为待核实（§9）。

### 3.8 时序窗口的用途

静态功耗只用转换时间（两个参照一致：OpenSTA 的功耗报告不用到达时
间窗口；RedHawk-SC 手册第 39 页——静态分析只用时序文件里的频率与转
换时间，时序窗口是动态分析另外才用的）。到达时间窗口首版不消费。

## 6. 数据结构（C++，前缀 PWR——裁定 12 既定）

```cpp
// 单引脚能量（逐实例对象内的条目）
struct PWRPinEnergy {
    CMPinId pin_id_;
    uint64_t rise_count_, fall_count_;      // 观测时长内的沿次数
    double rise_energy_j_, fall_energy_j_;  // 每次翻转的内部能量（焦）
    double load_cap_ff_;                    // 输出引脚：C_load；输入引脚：0
    double voltage_v_;                      // 供电电压（伏）
    uint8_t flags_;                         // 活动来源（实测 / 缺省）、转换时间来源、…
};
// 单实例功耗
struct PWRInstancePower {
    double leakage_w_, internal_w_, switching_w_, total_w_;
    CMVector<PWRPgSplit> pg_splits_;        // 按电源引脚的分项
    CMVector<PWRPinEnergy> pins_;           // 逐引脚能量（输入与输出）
    CM_FLAGS(uint8_t, no_internal_table, no_leakage_table, default_activity_used,
             default_slew_used, load_cap_missing)
};
// 分区正式对象 PART_{xp}_{yp}.POWER
class PWRPartitionPower {
    CMPartitionId part_id_;
    CMUnorderedMap<CMInstanceId, PWRInstancePower> items_;
};
// 汇总 "summary"：逐实例计数（总数、各类缺省与缺失的实例数、查表超界次数、
// 条件解析失败次数）、总功耗及三个分项、观测时长、内部单位声明
```

内部单位：功率瓦、能量焦、电容飞法、电压伏、时间秒。

## 7. 建库流程（三段式 + 直接任务链，先例复用）

1. **轻量预处理**：参数校验（五个前驱的句柄类型、settings / alpha）；
   确定分区集合（取设计库的分区表）；写入设置对象。master 不读任何
   大对象。
2. **提交根任务**（inputs 锚定五个前驱库的必要对象）。
3. **freeze** 只依赖汇总对象。

根任务体内：对设计库的每个分区提交一个计算任务；再提交一个汇总任务
（依赖全部分区的统计）。每分区计算任务在 worker 端组装上下文——设计
库本区的实例与连接、全部网的连接表（算接收引脚电容要用整张网的连接）、
单元库数据、波形库本区的活动对象、时序库本区的时序对象、寄生库本区
的网负载——逐实例按 §3 计算，产出 `PART_{xp}_{yp}.POWER` 与统计片
段。汇总任务归并统计、落盘、按汇总发消息（每族计数大于 0 才发一次）。

条件表达式的解析与求值（Liberty 的布尔表达式：`&`、`|`、`!`、`^`、
括号、引脚名、常量 0 / 1）是功耗库自己的一个小组件——单元库数据库
保持「只存原文」不动。

## 9. 测试规划

- **单元级（C++）**：表达式解析与概率求值；权重归一的四种情形
  （S < 1 有无条件组 / S < 1 无无条件组 / S > 1 / 单组无条件）；漏电
  的补足链；负载电容的三种来源；查表限幅；单位换算。
- **端到端**：对齐 `wf_small` 设计（14 个实例、16 个网）——寄生用阶段
  三的 `sp_small.spef`；活动与时序各手写一份小样张（翻转活动文件、
  时序窗口文件），数值手工可推导：选两个组合单元（反相器、二输入与
  门）和一个触发器，逐项算出期望值；其余实例断言计数与一致性关系
  （合计 = 三项之和；逐引脚能量 × 次数 = 内部功耗；按电源引脚分项之
  和 = 合计）。
- **对照**：`internal_energy_mode = average` 下，对同一个实例用独立
  脚本按 OpenSTA 的公式手算一遍，数值一致。
- **真实数据**：gcd 设计（`designs/` 子模块）全链走通——五个上游库
  都用真实数据建，功耗库出数；逐实例功耗为非负有限值、合计等于三项
  之和；与 OpenROAD 流程报告里的总功耗量级对照（只做量级参考——活
  动来源不同）。
- **不做的断言**：不依赖运行时间与任务完成顺序；期望值全部写成字面
  量。

## 10. 演进路径（不在首期）

- 活动传播（无矢量 / 部分仿真的场景）与时钟门控单元的专门处理；

## 11. 待裁定点（需要用户逐条裁定；每条附建议）

1. **内部功耗组的合并**：同一引脚上的多个组按条件概率加权累加（建
   议——OpenSTA 同款），还是只选一组？
2. **内部能量的沿口径**：分沿（建议——fly 的波形库有分沿计数，更直
   接；`average` 留作对照），还是一律取平均？
3. **没有活动的引脚**：取波形库的缺省值（建议；波形库现有缺省是翻转
   率 0、静态概率 0.5，用户可在建波形库时改），还是一律按 0，还是像
   OpenSTA 那样给缺省 0.1 / 0.5 并沿逻辑传播？
4. **时钟引脚没有活动条目**：同一般引脚（建议——首版保持简单），还是
   按时钟周期自动给每周期 2 次翻转？
5. **查表超界**：限幅并计数（建议——限幅不会算出非物理的能量；fly
   的查找表现有实现就是限幅），还是线性外插（OpenSTA 口径）？
6. **耦合电容的计入比例**：默认 1.0、用户可调（建议），还是固定值？
7. **条件里的非实例引脚（触发器内部状态）**：取 0.5 并计数（建议——
   首版没有状态概率的来源），还是让该组不计？
8. **缺省转换时间**：0（建议），还是取表的最小下标，还是要求用户必
   须给？
9. **消息前缀**：`PWRG`（建议——与 TIMG / WFMG / SPMG 同构，已核对
   未被占用）。
10. **落库粒度**：逐实例一个对象条目、按电源引脚分项（建议），还是逐
    电源引脚一行（RedHawk-SC 实例功耗文件的形态）？

## 12. 参照的做法（调研要点，出处见两份报告）

**OpenSTA（开源静态时序工具，源码阅读）**

- 活动只有两个数：每引脚「每秒翻转次数」与「为高的概率」，上升与下
  降不分开。缺省：输入引脚每最小时钟周期 0.1 次、为高 0.5，并沿逻辑
  函数向后传播；时钟引脚每周期 2 次；常量引脚 0。
- 内部功耗：同一引脚上的全部内部功耗组都参与，各乘概率权重后相加；
  上升 / 下降能量取算术平均再乘总翻转率。条件表达式化成二叉决策图，
  引脚代入为高概率，没有阈值。
- 查表线性插值、超界线性外插。输入引脚的内部功耗表用负载电容 0 查。
- 开关功耗 = ½ × 负载电容 × 电压² × 翻转率，只对输出引脚算；电压取
  `related_power_pin` 的电压名在库级电压映射里的值。
- 漏电按条件为真的概率加权；未覆盖的状态用无条件组补，没有才用
  `cell_leakage_power`。
- 功耗报告不用到达时间窗口，只用转换时间；不输出电流。
- 不支持的 Liberty 属性：内部功耗组的 `ps` 子组、`default_cell_leakage_power`、
  `default_voltage_map` 等。

**OpenROAD（开源布局布线工具，静态电压降分析）**

- 从功耗得到电流就是「总功耗 ÷ 电源网电压」，再在实例连到该电源网
  的所有引脚间均分；不区分内部、开关、漏电。地网用同一份功耗。回归
  测试全部使用 OpenSTA 的缺省活动。——fly 的裁定 7 明确不采用「功
  耗除以电压」。
- 电流注入位置：每个连到电源网的实例引脚，在引脚图形的平均中心处
  一个节点；未放置、引脚无图形、没有 Liberty 单元的实例不注入。

**RedHawk-SC（用户手册 Release 2024 R2）**

- 功耗视图是补充视图，存每个实例的功耗；来源有导入实例功耗文件、按
  翻转率与占空比计算等（第 23、69 页）。
- 逐实例功耗 = 漏电 + 内部 + 开关，按电源引脚存放（第 162、169 页）。
  公式：内部 = ½ × 翻转率 × 频率 × 平均内部能量；开关 = ½ × 翻转率 ×
  频率 × 电容 × 电压²（第 162–163 页）。
- 漏电对 `leakage_power` 组按状态概率加权，全不匹配时退回
  `cell_leakage_power`（第 162 页）。手册没有给功耗视图自身的缺省翻
  转率与缺省静态概率；实例功耗文件未覆盖的实例不指派功耗（第 163
  页）。
- 负载电容 = 接收引脚电容 + 网络电容；信号网开关功耗里耦合电容的计
  入比例手册未提及（第 163、306 页）。
- 静态分析只用时序文件里的频率与转换时间，时序窗口是动态分析另外才
  用的（第 39 页）。
- 静态平均电流 = 平均功耗 ÷ 供电电压（第 150、178 页）；电流汇位置
  称为虚节点，每个引脚一个或多个（第 102、106 页）。

**与 fly 的差异（设计上有意不同之处）**

- 电流不用「功耗除以电压」（裁定 7）——电流库另定。
- 活动的未知态 / 高阻态单独统计，口径由波形库的设置决定。
- 分沿计数可用，内部能量按沿分开算（待裁定 2）。

## 13. 未核实与调研缺口

- Liberty 规范原文：内部能量表的单位规定、压缩表的定义、`ps` 子组的
  语义。
- OpenROAD 内嵌的 OpenSTA 比上游旧，三处语义不同（条件的求值方式、
  漏电的归一化、传播活动的上限）——本方案以上游版本为准。
- OpenSTA 的条件权重还包含「输出函数对该输入的布尔差分」这一因子，
  本方案首版只取条件为真的概率（更保守也更简单）；差异的影响没有量
  化。
- 触发器内部状态变量的概率来源（OpenSTA 的做法没有读到）。
- fly 的单元库解析器对内部功耗组的 `ps` 子组的处置（静态阅读的结
  论是「当作普通表收集」，没有用样例验证）。
